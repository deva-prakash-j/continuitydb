# Governance

ContinuityDB uses maintainer review with transparent public design discussion.

- Backward-compatible fixes and documentation need one maintainer approval.
- API/storage/security boundary changes need an issue, migration plan, tests and
  two maintainer approvals.
- Releases require the full release check and published raw benchmark artifacts
  for any new performance claim.
- Security reports follow `SECURITY.md` and may be fixed privately before public
  disclosure.
- Project names, package publication and release signing remain maintainer-owned
  actions.

This policy can evolve as the contributor group grows. Material changes should
be proposed publicly with a transition period.
