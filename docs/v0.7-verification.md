# ContinuityDB v0.7 verification

This is the verification contract for the v0.7.0 zero-instruction agent
integration. It records what local checks prove and what still requires
exact-head native CI and independent Astraea review. It does not claim that an
unpublished tag or unavailable native run has passed.

## Complete setup

From a Git repository, one command registers the project and installs every
detected complete adapter:

```bash
continuitydb setup --agents detected --project-dir "$PWD" --apply
```

Use `--agents all` to generate all five supported adapters. Use `--mcp-only`
only when tool exposure without lifecycle or managed instruction assets is the
intended behavior. Generated project identities are registered, concrete IDs;
the adapters do not generate an implicit fallback project or a wildcard grant.

| Client | Recall mode | Managed assets |
|---|---|---|
| Codex | `policy-led` first-task recall | `.codex/config.toml`, `AGENTS.md` |
| Claude Code | `hook-enforced` startup/resume/compact recall | `.mcp.json`, `.claude/settings.json`, `CLAUDE.md` |
| OpenCode | `plugin+policy`: plugin compaction recall, policy-led first task | `opencode.json`, `.opencode/plugins/continuitydb.js`, `AGENTS.md` |
| Cursor | `hook+policy`, including policy fallback for read-only cloud startup gaps | `.cursor/mcp.json`, `.cursor/hooks.json`, `.cursor/rules/continuitydb.mdc` |
| VS Code Copilot | `policy-led` first-task recall | `.vscode/mcp.json`, `.github/copilot-instructions.md` |

Codex and Copilot are not described as hook-enforced. OpenCode's plugin enforces
compaction recall, while its first-task recall remains instruction-led.

## Capture and trust boundary

All five adapters report `capture_mode: explicit-governed`:

- `memory_capture` is used only when the user explicitly asks to remember,
  save, record, or update a durable fact;
- only a compact durable claim is submitted to server-side sensitivity,
  conflict, duplicate, idempotency, and lifecycle policy;
- ordinary prompts, raw transcripts, conversation records, tool logs,
  credentials, secrets, hidden reasoning, and temporary task state are never
  auto-captured;
- recalled text is bounded, project-scoped untrusted evidence, not permission
  or executable instruction;
- plan, read-only, sandbox, and approval restrictions are never bypassed; a
  denied or unavailable write is reported truthfully as `not saved`.

Stop/idle automation can read only the explicit structured
`.continuitydb-handoff.json` checkpoint. It does not synthesize a checkpoint
from a transcript.

## Local gate

The release candidate must pass these commands without skipped required checks:

```bash
node --test test/client-adapters.test.js test/release-workflow.test.js
npm run validate:clients
npm run validate:release-workflow
npm run release:check
npm run test:binary
npm run test:binary:semantic
npm run test:binary:reproducible
git diff --check
```

`validate:clients` generates all five adapters, independently verifies their 12
unique assets and four managed policies, validates every MCP/hook/plugin schema,
discovers and semantically validates all 12 shipped client examples so none can
be silently omitted or retain stale commands/references, and compares all four
generated examples with actual output. The same exported tree validator checks
adapter files emitted by the standalone binary smoke.

## Native and publication gates

CI is configured to run blocking adapter validation in the Node 22, Node 24,
container, Linux binary, Linux x64, macOS arm64, and Windows x64 paths. The
release workflow must reach terminal success for every supported native matrix
entry before checksum verification, provenance attestation, or publication.

The supported native release set is exactly:

```text
continuitydb-linux-x64
continuitydb-linux-x64.sha256
continuitydb-darwin-arm64
continuitydb-darwin-arm64.sha256
continuitydb-win32-x64.exe
continuitydb-win32-x64.exe.sha256
```

After publication, the workflow downloads that exact six-file set, compares
every downloaded file byte-for-byte with the verified build input, validates
all checksum sidecars, verifies provenance for every asset, and rechecks the
release identity. Reruns update the same commit-bound main prerelease only after
verifying its full commit SHA. Pushed version tags remain the stable path,
including `v0.7.0`.

Intel macOS is npm/source-only for v0.7.0 because the upstream Node SEA runtime
crashes on x64 macOS. No Intel macOS standalone binary is published.
